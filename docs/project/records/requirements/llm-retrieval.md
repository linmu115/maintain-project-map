## 本次实施

查询支持多个关键词、类型筛选、合理排序和命中原文片段；精确 ID 和名称优先。当前接口、模块与实现不因背景历程中偶然出现关键词而被挤到后面。默认查询当前状态，历史可显式查询，部分匹配和未读范围可见。

LLM 默认返回短候选和正文所需定位；完整元数据按需取得。来源以明确角色、工作区、路径、可选符号和可用性呈现，不把地图仓库当作源码仓库。

用户已进一步明确要求将混合检索与 RRF 加入 LLM 侧功能。沿用现有查询入口，在相同项目、类型、模块和状态范围内分别做词面与语义检索，按排名融合并去重；精确 ID/名称仍优先，结果保留原文定位，分数不表示事实置信度。

采用本地中文嵌入模型和可重建缓存，更新时只重算变化内容；缓存隔离地图位置和模型版本，不使用过期正文。默认自动使用已配置的本地能力；不可用时明确降级为词法，显式要求混合时不可伪装成功。保留纯词法查询，不增加常驻服务或第二套聊天入口。

## 本次继续实施：源码发现与说明归档

地图可位于项目开发区并与源码仓库并列，位置索引和源码工作区绑定由 LLM 维护；多个仓库、分支和工作树不能猜测对应关系。已有位置不因本条需求自动批量迁移。

从绑定工作区发现源码入口、依赖和未登记关系，优先供 LLM 读取，人读页面只需小文档栏目。源码变化先提示待复核；确认失效后将旧说明移入归档，当前人读展示和 LLM 默认查询排除归档正文，旧 ID 保留版本、原因和后继。归档说明不等于退役功能或撤销需求。

用户已明确要求继续完成源码入口/依赖自动发现和确认失效后的文档物理归档。扫描只作用于显式绑定的 Git 工作区，覆盖当前工作树的已跟踪和未忽略的新文件；输出静态证据、解析范围、未解析项，以及与地图模块/接口的对应和待补登记候选。人读入口是项目文档下的小栏目；LLM 可按需查入口、依赖、符号、登记缺口和待复核说明。

源代码变化只能产生待复核提示。LLM 核对说明与当前源码后，可登记仍有效的核对基线，或带理由和证据归档已确认失效的说明。归档保留原始文件内容、ID、旧路径入口、版本和替代记录；没有新版时显示说明缺口。默认 LLM 与人读当前查询不加载归档正文，只有显式查看历史才展开。有效需求不因说明归档撤销，功能状态保持独立；绑定的外部原文也不被顺带删除。

不增加多跳问答或自动阅读线索，不承诺静态扫描能穷尽反射、运行时注册或所有语言的依赖。
