# 组合项目的模块层级与扩展接口

项目成员以用户确认的范围与明确成员声明为依据，再用源码核对职责。仓库相邻、一起安装、共用协议或存在包依赖，不足以建立共同父项目或父子模块。协议表达通信约定，可按运行位置分组并用关系线说明依赖。

已有独立地图的外部提供方保留自己的模块和合同；本地图用项目 ID、必要条目 ID 及自己的接入说明关联。在图中需要出现外部依赖时，将其置于项目成员边界之外并标明外部身份。本 Skill 的地图只维护自身能力，DSH Suite、Session Maintenance、ThoughtDAG 是使用方或案例。

地图应让开发者单独理解模块及必要的子模块。拆分依据职责、对象归属、接口、适配对象和维护边界，不按文件数量机械展开。例如平台会话 Adapter 与业务插件 Adapter 分别组织说明与合同入口，即使共用加载器，也不能合并其数据或权限语义。

提供方模块保存唯一完整合同及已知接入者链接。消费方保存自己接入哪个模块、哪项接口、涉及什么功能及适配状态，并链接回合同和提供方接入目录。关联入口面向开发者导航，LLM 查权威合同；不复制另一份接口规格。用户明确纠正：此处不要求新增从开始到结束的用户旅程文档。

架构图应按真实模块边界框出相关内部功能，显示扩展接口和接入方；流程图在有执行依据时按负责组件采用泳道/分组。已知关键结构不能仅以插件名称列表或“正常/异常”两行替代。用户认可带模块边界和接口连接的图形表达。

Skill 用短入口按需加载专门说明，日常小任务不强制重新分析全项目。目录树、正文导航与关系去重的要求见 [[REQ-reader-navigation]]，实际结果另见 [[IMP-reader-navigation]]；现有地图的重组和多图导航分别以其实现证据判断。

2026-09-16 补充：耦合判断必须可迁移。模型按“消费方的具体能力 → 实际接口 → 用途与归属”核查，区分直接调用、间接依赖、计划与未核实范围。不能从一个入口调用某接口推断整个模块的保存、删除或展示都依赖同一接口。规则应适用于其他软件、工作流和 Skill，DSH 只作为验证样本。
