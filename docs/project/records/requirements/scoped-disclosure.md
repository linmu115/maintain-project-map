# 面向 LLM 的命令查询与局部资料披露

本记录保存[系统地图扩展总需求](system-map.md)中的查询与局部维护细则；增强实现见 [[IMP-system-map]]，检查证据见 [[VER-system-map]]。

## 已有基础与增强目标

现有 project_map.py 支持 --help，以及 search、read、related、resolve 等子命令。search 返回有限候选，read 返回指定记录和续读信息；related 只返回登记关系，不自动打开跨项目正文。脚本本地加载整个地图模型不等于将全部记录送入 LLM。完整 HTML 和导出 JSON 是阅读产物，不作为普通开发的默认模型上下文。

系统元图和子图是开发者阅读入口。模型可以直接定位当前模块，不必先读父图或依次遍历全部祖先页面。已知源码位置且任务简单时允许直接阅读源码。

## 三层披露

1. 定位：名称、职责、别名、状态、源码位置和接口入口。
2. 局部工作材料：本次有效需求、相关实现、适用约束和涉及的合同。
3. 扩展材料：受影响消费者、历史决定、验证证据及其他项目资料，按任务需要继续查询。

命令帮助先给出子命令与用途，再通过子命令 --help 披露参数和实例。未来模块检索、接口目录和影响范围命令需要清楚标记返回范围、截断、未解析引用和继续读取方式。具体子命令名称待实现设计，不能在帮助中列出未实现能力并使其看似可用。

## 局部维护与版本

项目、模块、记录和图使用稳定身份；目录变化不改变身份。按相关记录和实际源文件内容识别是否过时，多仓库数据不能用一个仓库的 Git HEAD 代表。

- 私有实现改变而外部行为不变：维护受影响模块。
- 子图仅补内部细节：维护该图及绑定。
- 模块职责或对外能力改变：检查模块入口和相关系统概览。
- 接口语义、权限或生命周期改变：核对唯一合同、已登记消费者及必要验证。
- 功能删除、合并或退役：修复旧身份、后继、链接和相关图节点。

查询预算用于控制返回量，不能静默截掉重要约束后宣称范围完整。候选不足或索引过时时可扩大有依据的查询并回到源码。未登记关系不代表不存在依赖。反向索引只覆盖已登记地图和实际声明，失效、缺失与未核实状态应可见。

## 职责分工与暂缓内容

Archify 负责单张图的布局、渲染、校验和图内交互；地图阅读器负责系统/项目阅读入口、项目护照中的新标签页打开及条目关联，原标签页保留阅读位置；检索工具负责为模型定位模块、合同及源码。当前页内部返回保留已有行为，不为系统进入项目强制引入跨地图返回栈。按需加载领域说明，不要求普通开发读全部实现或图形 JSON。

MRS 组合、性能 benchmark 和 DSH 浏览器插件按用户要求后续再考虑。本轮不因记录这些需求而启动相应开发、实验或安装。

## 验收目标

- --help 和子命令帮助可发现实际能力，普通查询有明确上限与继续入口。
- 一个模块的局部任务可直接找到必要要求、合同和源码，不强制读全图。
- 无关模块变更不要求重复加载未变材料；合同变更可查询已登记消费者及缺口。
- 能区分本地扫描量、模型实际收到的文本量及未读取材料；不把字符数当成 token 成本或效果证明。
