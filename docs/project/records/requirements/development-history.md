# 面向开发者阅读、面向模型按需查询的开发历程

沿用现有 HTML、UI 模板、侧栏和返回功能，在“更新记录”下方放置“开发历程”。列表显示任务标题、时间、涉及模块、结果和摘要。任务正文依次说明问题、主要尝试、实际反馈、关键转折、结果与保留边界。每段可展开来源，长命令和输出按需加载。默认以文字阅读，不要求生成完整事件树或泳道。

叙述是可修订的整理材料，须标注覆盖范围和证据引用。缺失选择原因时注明未记录，推断不得冒充原始理由。模型只按需要查少量候选、相关事件及其上下文，再继续读取；返回截断和未读范围，工具调用与返回可以配对。失败结果附适用条件，不自动成为禁用规则。普通项目查询不读取事件载荷，也不要求每次开发先查询历程。

复用宿主已有记录，首个实例限于本任务中已完成的“研究地图改为策略泳道”。仅索引用户消息、公开答复、工具调用及返回；排除隐藏推理、系统指令和其他任务。保留稳定来源、时间、调用身份、内容指纹和范围，不修改宿主日志，不承诺从日志恢复全部代码。索引可重复执行，已索引内容改变应报错；修订叙述不覆盖原始依据。

用户在实施中进一步指出：Codex 已保留会话，地图不应重复保存全部工具调用和输出，也不应占用多余上下文。因此默认只保留叙述及来源定位索引。用户展开或模型请求时才向原会话按段读取并校验指纹；原会话移走、删除或内容改变时明确提示。已生成的重复原文副本应移除。全文搜索可在本地读取选定任务以找到候选，但返回给模型仍是有限摘录。

验收包括真实实例可读、依据按需加载、配对与继续读取、来源缺失明确提示、地图往返与窄屏阅读，以及现有查询和阅读回归。更新记录继续遵守用户明确要求才新增的规则。

## 按问题查找与按任务回顾

2026-09-17 用户确认同时提供两种入口，并要求应用到本 Skill 的开发地图。任务保留完整叙述；有复用价值的问题、尝试、排错、改进、验证和人工纠偏可整理成独立经验，引用所属任务的原始依据。经验按工作类别、尝试结果和模块筛选；失败与后续修复分别说明，不因为最终完成而抹去负结果。模型可以只查经验摘要再自主展开。

同一经验可以出现在多个分类中，正文只维护一份。每个侧栏入口具有独立位置：点击一个分类下的文档，只选中该入口，不自动展开或高亮其他分类下的同一文档。用户主动展开的文件夹、侧栏滚动位置、筛选和返回状态应保持。直接链接包含阅读方式和入口分类，刷新及前进后退不丢失位置。原有仅含任务的地图和旧链接继续可读。

## 地图更新时主动维护

2026-09-17 用户进一步要求：Skill 提示应让 LLM 每次更新地图时主动更新开发历程。新建或实质修改地图内容后，交付前同步本次任务的问题、尝试、反馈、修正、结果与范围；同一任务补充原记录，短修订简记，有复用价值再提炼经验。无需用户重复提出收录要求。

纯阅读、查询和内容不变的 HTML 导出不重复记账，修改历程也不递归产生新历程。不编造失败、原因或证据，不自动补齐全部旧任务。主动写入与按需读取分开：原会话仍保存原文，模型自主决定是否查历史、读取多少。来源不能索引时保留明确标为待绑定的草稿，不能声称正式历程已完成。
