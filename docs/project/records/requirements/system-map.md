# 功能更新需求：在项目地图上扩展系统地图

## 文档状态

- 需求日期：2026-09-16。
- 需求身份：REQ-system-map，沿用原系统元图需求 ID。
- 状态：当前确认的开发要求；功能已实现，覆盖与限制见 [[VER-system-map]]。
- 本文是本次更新的总需求入口；模型检索细则见[命令查询与局部资料披露](scoped-disclosure.md)。
- 实现见 [[IMP-system-map]]；实际检查独立存入 [[VER-system-map]]，本文的验收条件不自动等于全部实测通过。

## 1. 更新定位与目标

在现有项目地图基础上扩展系统地图能力。项目地图继续维护单个软件、组合项目、工作流或 Skill 的需求、对象、模块、接口、实现和证据；系统地图面向用户明确维护的开发对象，汇集其收录项目之间的协作。

例如，用户可以为自己的 DSH 会话、引用与知识组织系统建立系统地图，从整体理解 Annotation、Sidechat、ThoughtDAG、Obsidian 侧引用、贴纸和 Session Maintenance 的关系，再进入各项目继续阅读。

这是产品能力的超集扩展。普通项目地图仍可独立使用，既有项目 ID、记录 ID、文件绑定、原生图及阅读链接保留。系统地图按其职责选择界面；能力扩展不要求系统页面显示所有项目级面板。

目标是让开发者看清系统组成与接口关联，同时让模型按当前开发任务直接定位局部材料。系统总图的存在不构成模型每轮必须读取总览、所有项目或所有图形的要求。

## 2. 系统范围与关系模型

### SM-01 明确收录，保留项目自治

系统地图有自己的稳定身份、开发对象说明和明确收录清单。收录单位是已有项目地图；一个项目可以包含多个仓库或插件，不要求每个安装包单独建图。同一项目地图可以被多个系统地图引用，权威内容仍由原项目维护。

收录范围由实际维护对象和用户选择确定。目录相邻、共同安装、包依赖或强耦合只提供分析依据，不自动纳入所有传递依赖。有关但未收录的提供方可显示为外部依赖；已收录、外部引用、待确认关系需要能区分。

系统地图维护系统范围、系统级设计决定和确属跨项目的协作要求。子项目的详细需求、实现、接口合同、验证及历史继续留在各自地图，系统聚合页不制造另一份完整档案。

### SM-02 表达一般图关系

支持多对多、交叉、双向和循环依赖。同一个项目或接口保持唯一身份，不因多个消费者而复制。左侧目录可以分组，但目录树不决定依赖形状，也不强迫项目具有唯一父级。

区分收录或归属、接口提供与消费、数据交接及实际执行顺序。系统整体组织图主要解释结构和协作，依赖线不自动成为执行流程。关系只写有依据的当前事实，保留计划、未核实和失效状态。

## 3. 接口汇集与系统阅读页面

### SM-03 提供方合同唯一，系统汇集入口

系统接口目录展示接口名称、提供项目、面向开发者的用途说明、权威合同位置、已登记消费者及其接入说明。消费方说明自己使用哪项能力、影响哪些功能，并链接提供方合同。系统页汇集或派生这些入口，不另写完整参数、状态机和兼容合同。

例如 Session Maintenance 的 Harness Adapter 与业务扩展 Adapter 应分别呈现。Annotation Core 被多个项目调用时仍指向同一权威身份，不能把各入口的接入说明误当成多份 Core 实现。反向目录说明已登记覆盖范围，未登记不代表没有其他消费者。

### SM-04 系统页面按系统职责组织

| 入口 | 系统地图内容 |
| --- | --- |
| 系统概览 | 开发对象、收录边界、组成项目及职责、系统级设计说明、Archify 整体组织图 |
| 接口与关联 | 提供方、接口类别、已知消费者、接入说明、关系定位和权威记录链接 |
| 收录项目 | 已收录地图的位置与状态，支持找到相应项目和图中节点 |
| 更新记录 | 用户明确要求留存的系统级迭代；不自动复制子项目的全部更新 |

这些是所需阅读内容，具体栏目排布可在实现中细化。系统地图不显示功能路径图入口或空占位；实体项目继续保留自身项目概览、项目条目、更新记录以及适用的架构或流程图入口。当前 Skill 自身仍是一张项目地图，其已有功能路径不因新增系统类型而删除。

沿用当前阅读器样式和图内基本操作。提问继续在现有会话 harness 中进行，不新增独立提问入口。

## 4. 项目卡片、语义护照与新标签页

### SM-05 点击先查看护照

点击系统整体组织图中的项目节点，先在当前图中显示放大的语义护照卡片，沿用现有 Archify 护照的阅读方式。点击节点本身不直接跳走。

项目护照展示项目名称、职责、当前关联或接口入口、地图可用状态和明确的“进入项目”按钮。项目记录链接等既有护照内容按实际关联保留，不把护照变成另一份完整项目文档。

### SM-06 进入项目时新开标签页

用户点击“进入项目”后，浏览器新建标签页，打开目标项目地图并定位到声明的目标图。新标签页使用目标项目自己的标题、左侧栏、项目概览、项目条目、更新记录和模块目录，不能只显示一张脱离项目入口的原生图文件。

原系统地图保留在原标签页，选中项目、护照、画布缩放与平移、正文和侧栏滚动位置、筛选状态均保持。用户通过切换浏览器标签页继续阅读原系统图；本次扩展不要求建立跨项目的单标签页返回栈。现有项目页内部的返回功能继续按原职责工作。

跨项目进入不增加输入输出卡片。本次操作是打开另一张维护地图；模块内部递归子图和 input/output 展开不属于本次功能实现范围。

系统可从不同入口引用同一个项目。每个系统标签页保留自己的阅读状态，不向目标项目写入唯一父级或来源归属。项目地图仍支持不经过系统元图的直接访问。

### SM-07 目标解析与不可用反馈

项目节点绑定稳定的项目身份和图身份，必要时绑定模块或记录身份。机器路径、工作树及临时本机 HTTP 地址在打开时解析，不作为长期身份存进关系定义。

项目目标应能确定到实际地图及图；存在多个合理工作树时使用明确选择，不猜另一个同名项目。地图未登记、文件缺失、目标图失效、预览不可用或新标签页未能打开时，护照内说明缺口并保留当前页，不假装成功，也不静默改为当前标签页跳转。可提供对应的重试或可见链接。

## 5. 面向 LLM 的查询与局部维护

### SM-08 命令帮助与分层披露

继续使用可发现的 CLI。现有 project_map.py 已支持 --help 及 search、read、related、resolve；新增能力应有子命令帮助、明确返回范围和可继续读取的位置。具体新增命令名与参数待实施确定，不在本文冒充已存在的命令。

模型按任务读取三层材料：定位信息；相关需求、实现、约束和合同；必要时扩展到消费者、历史与验证。支持直接定位某项目、模块或接口，不要求先读系统元图。已知源码位置的小任务可以直接读源码。

图形页面和完整导出不默认送入上下文。脚本本地扫描记录不等于向模型披露全部正文；查询结果应限制候选数量和正文范围，并显式说明截断、未解析引用及覆盖缺口。重要约束不能在静默截断后被当成已核实完整。

需要增强模块范围查询、系统接口目录定位、跨地图已登记关系的反向查询及局部资料版本识别。详细要求唯一维护在[命令查询与局部资料披露](scoped-disclosure.md)。

### SM-09 按变更影响维护

项目、模块、记录和图使用稳定身份。记录及实际源文件摘要用于识别过时材料；多仓库数据不能由单个仓库 HEAD 代表。派生索引可重建，不能成为与原始资料竞争的权威来源。

| 变更 | 需要检查的范围 |
| --- | --- |
| 私有实现改变，对外行为不变 | 受影响模块及相关记录 |
| 局部图补充内部细节 | 该图和节点绑定 |
| 项目职责、对外能力或系统收录变化 | 项目入口及相关系统总览或目录 |
| 接口语义、权限、生命周期变化 | 唯一合同、已登记消费者接入及必要验证 |
| 功能删除、合并或退役 | 原身份、后继、失效链接与有关图节点 |

无关修改不要求重写所有上层说明或重新读取未变正文。索引失效或召回不足时可回到源文件核对；不把查无结果当成没有依赖。维护更新和页面生成不自动追加开发者更新记录。

## 6. 复用与实现职责

| 部分 | 本次职责 |
| --- | --- |
| 原生 Archify | 单张整体组织图的模型、布局、渲染、校验与图内交互 |
| Map Skill 阅读器和适配层 | 系统页面、接口聚合展示、项目护照扩展、目标解析及新标签页打开 |
| 地图检索工具 | 身份和位置解析、模块或接口定位、已登记关系查询、有限正文返回 |
| 原项目维护资产 | 唯一需求、实现、合同、来源与验证 |

优先复用原生语义护照并在适配层增加项目入口。保留原生图源、上游代码身份和生成副本的区分。实现不为本功能另造版本控制或复制 Git/工作树机制。

## 7. 验收条件

| 编号 | 场景 | 预期结果 |
| --- | --- | --- |
| AC-01 | 现有项目未被任何系统收录 | 仍能独立访问、查询、维护和生成页面，原身份与链接有效 |
| AC-02 | 多个项目消费同一个 Core 接口，并存在交叉或循环关系 | 总图表达一般图关系，合同身份唯一，不强制树化 |
| AC-03 | 浏览系统概览及接口目录 | 能区分收录边界、外部提供方、不同 Adapter 家族和接入范围；无功能路径入口或占位 |
| AC-04 | 点击系统图中的 ThoughtDAG 卡片 | 当前标签页打开语义护照，可见“进入项目”，尚未跳转或新开标签页 |
| AC-05 | 点击护照的“进入项目” | 新标签页打开 ThoughtDAG 的项目地图并定位目标图，标题和侧栏均属于该项目 |
| AC-06 | 从项目新标签页切回原系统标签页 | 原护照、选中节点、画布位置、滚动和筛选保持；没有跨项目输入输出中间卡片 |
| AC-07 | 两个系统分别引用同一项目 | 共用项目权威资料，各系统阅读状态独立，项目无唯一父级假设 |
| AC-08 | 地图、工作树、图目标或预览无法明确解析 | 护照给出具体状态，不误开另一项目，不伪称成功，不悄悄替换原系统页 |
| AC-09 | 查询 --help，再定位某个局部模块或接口 | 帮助只披露实际能力，查询返回有限结果、来源和继续入口，不强制读取总图或全部成员 |
| AC-10 | 改一个内部实现，随后改一个公开接口 | 前者按局部范围维护；后者能查询已登记消费者并报告未知覆盖，不要求所有项目全文重写 |
| AC-11 | 新增系统地图后打开普通项目地图 | 普通项目仍有自己的条目和适用图入口，不因系统页无功能路径而全局删除该功能 |

实现验证记录应另存并关联本需求。结构校验、渲染成功或字符数下降不能代替上述行为验收，也不能证明后续开发成本收益。

## 8. 本次范围之外

MRS 组合、性能 benchmark、DSH 浏览器控制插件留待后续；不在本次需求落地中自动开展。模块内部递归展开及 input/output 卡片也不包含在本次系统地图交付范围。本文不要求重新划分或修改实际 DSH 插件源码、替换运行实例，或立即构建所有项目的系统地图。

具体 schema 版本、配置字段、CLI 命名、预览服务组织和聚合缓存实现，由后续实现设计确定，但需要满足本文的身份、职责、阅读和披露要求。
