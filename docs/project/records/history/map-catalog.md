# 用项目名称找到本机地图

## 问题

用户希望调用项目地图 Skill 并提到项目名后，模型直接找到本机地图，不再要求反复提供目录。原注册表已有项目 ID 与路径，但入口没有按名称查找和持续补齐别名的能力。

## 初次尝试与人工纠正

首次把“研究地图的位置”理解成同时收录 MRS 研究地图，因此读了 B/C 题的导航清单，并试写了研究地图登记分支。用户指出本任务改的是项目地图 Skill，B 题属于 MRS，两者不应混为同一目录。

据此移除研究地图适配，只保留 project-map/v1。试写未登记真实研究项目，未修改它们的研究文件或配置；MRS 软件自身的开发地图仍是普通项目地图。测试加入对研究地图清单的明确拒绝。

## 实现与验证转折

保留原有项目 ID 注册表，增加名称、别名、分页检查和明确默认工作位置。重名或多个无法判断的工作树保持候选；默认副本丢失时不自动跳到旧副本。调用 Skill 时才定位，再由模型按需读正文或历程。

第一次默认位置兼容性复验失败。排查发现测试临时目录处于本机用户目录的 Git 根下，两个虚拟工作位置均被识别为同一工作树，触发真实的歧义保护。随后在该单元测试中隔离 Git 环境，单独验证无工作树上下文时的默认选择，保留生产逻辑对多个当前候选的谨慎处理。复验地图核心 38 项通过。

## 结果与边界

本机 10 个项目、11 个工作位置已登记，26 个示例、评估和历史项目地图文件只在盘点说明中列出排除原因。当前用户目录、D 盘及 C 盘部分非系统工作目录已扫描；权限受限目录和报告中的访问错误不在完成覆盖之内。

Skill 入口明确新建、接入、搬迁、重命名和实质更新时主动核对登记。目录只保存少量元信息；不会把地图、日志或工具载荷集中注入每次上下文。源稿与已安装版本同步，最终检查范围见 [[VER-map-catalog]]。
