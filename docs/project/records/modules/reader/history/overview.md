# 开发历程与按需证据

开发者在“更新记录”下方打开任务历程，先读为什么这样推进，再按需展开对应依据。正文由有来源的整理组成，链接当前需求、实现和验证；不会用完整工具事件树代替叙述，也不会因新增历程自动生成图。

地图只保留公开事件的定位、时间、调用身份及指纹。原文继续由 Codex 保存；原会话丢失或改变时，正文仍能读，依据入口明确提示。模型可直接继续工作，也可按问题查询相关历程；常规地图查询不打开原始事件。

维护写入由 Skill 指引触发：每次新建或实质更新地图，主动同步本次任务历程；同一任务续写，必要时提炼经验。纯浏览和内容不变的重导出不记新任务。此要求不改变模型自主查询历史的方式，也不让阅读器承担后台采集。

详细合同见 [[IF-history-query]]，实际边界见 [[IMP-development-history]]，用户要求见 [[REQ-development-history]]。

“按问题查找”将有价值的排错、改进、验证和纠偏整理成经验，可按工作类别、尝试结果和模块筛选；“按任务回顾”连接完整过程与这些经验。一个经验可以在多个类别出现，各入口保留独立导航位置，正文和来源只维护一份。真实的本项目案例见 [[HIST-source-reuse]] 与 [[EXP-source-reuse]]。
