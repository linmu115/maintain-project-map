# 开发历程的当前实现

来源入口为 `scripts/development_history.py`。已支持 Codex 指定 JSONL 文件及明确行范围，白名单索引公开消息和工具事件；保存原生 ID、调用配对、行与文本指纹。索引可重复执行但不覆盖不同内容，摘要和机器查询均不会自动拉取整轮原文。

阅读记录使用 `kind: history`，正文是人类叙述，事件链接按需打开。`assets/development-history.js` 集成到原 `reader.html`，侧栏位于更新记录下方；默认无事件树、无新画布。长文本每段默认 2000 字符，继续读取由读者触发，返回时保留已读片段。没有来源时显示具体缺失原因。

`render_map.py` 导出叙述、紧凑事件目录和仅由本机服务使用的来源绑定清单，工具载荷不写入导出文件。`serve_map.py` 从已绑定的原会话核查并返回请求片段；旧预览服务遇到新增能力时会重启到支持版本。B 题自定义阅读器没有提供该功能数据时沿用原栏目，保留注入挂接点。

真实实例放在 MRS 维护地图的 `HIST-research-swimlanes`：2026-09-17 11:26–11:55 的公开任务，126 个事件定位、59 组完整调用。记录说明拆分研究分支的公开理由、布局检查失败与修正、阅读往返和交付范围。早先试做的工具原文副本及其导出片段已按用户反馈移除。

当前仅支持明确选定的 Codex 来源，没有自动采集、向量索引、全事件图或脱离原会话的完整证据归档。源会话被删除后仍能阅读整理正文，无法展开原文。检查范围见 [[VER-development-history]]。

## 两种阅读入口与经验查询

同一 HTML 已提供“按问题查找”和“按任务回顾”。`kind: experience` 保存有独立复用价值的问题，引用所属任务和已有实现、验证；工作类别、尝试结果与模块可以组合筛选。任务原有过程仍保留，并列出其中的经验。模型新增 `cases` 查询，返回少量去重摘要后自主展开。

导航位置包含阅读方式、分类或任务及经验身份。相同正文在不同分组下分别选中，只展开所选入口；手动展开状态、侧栏位置与返回状态分别保留。链接携带入口和筛选，旧任务链接继续进入任务全程。

本项目自身已收录 [[HIST-source-reuse|原会话复用的开发过程]]、[[EXP-source-reuse|用户纠偏与存储改进]]、[[EXP-evidence-boundaries|有限读取及失效范围的核对]]。它们共用 38 条公开事件定位，不保存新的工具原文副本。MRS 维护地图另从原有泳道任务整理出方案拆分和布局排错两条经验。

## 主动同步的提示规则

Skill 入口与开发历程参考已明确：新建或实质更新地图内容时，模型在本次交付前主动同步当前任务历程。同一任务续写，短修订简记，仅对有独立查找价值的问题提炼经验；纯查询、重导出和历程自身编辑不重复生成任务。

这是指引层的维护职责，没有新增后台自动采集器，也没有要求模型每次先读全量历史。公开来源仍按任务范围索引，原文按需读取。本次规则修订过程见 [[HIST-proactive-history|让地图更新主动带上开发历程]]。
