# 本次检索改进过程

来源：2026-09-19 当前 Codex 任务中用户关于 Graphify 与本机项目地图的对照、检索体验及批注。仅整理当前可见讨论；未导入宿主会话事件索引，属于待绑定来源的过程草稿。

检查发现搜索原先将整句话作为子串，且默认包含历史状态。实现多关键词、类型筛选、明示回退和简短输出。首次中文回退把跨词双字也计入覆盖要求，测试暴露漏召回，调整为已存在的字面片段并保留部分匹配标记。独立运行原单测又暴露测试路径依赖其他测试的导入副作用，补全测试自身的脚本路径设置。

来源读取采用显式工作区和可选已核对指纹；文件变化只提示待复核。未接入远程模型、自动依赖扫描或移动地图。实现与验证分别见 IMP-llm-retrieval、VER-llm-retrieval；没有对照实验支持普遍准确率或 token 收益。


用户随后明确要求把混合检索与 RRF 加入 LLM 侧，继续沿用先前的类型筛选、短返回、显式工作区和历史边界；不是要求新增多跳问答或阅读线索。选择本机已有 ONNX Runtime 和分词器，固定中文 BGE small 的模型版本与校验值，项目文本不送给远程嵌入服务。

实现中分别保留词面和语义候选，用 RRF 去重合并；段落向量缓存按地图位置与模型隔离，变化后从实时记录更新。测试发现 SQLite 的事务上下文不会自动关闭连接，导致 Windows 文件占用；改为显式关闭后，缓存重建、删除和临时目录检查通过。查询真实地图时看到零碎词面重合和半段片段影响判断，扩大混合模式的中文词面候选，并优先按段落切分；链接目的路径不进入嵌入文本，原文仍完整保留。

真实模型首次四记录试查中，“开机后第一步做什么”的目标排第二，原先第一名断言失败；不能把小模型视为准确答案排序器。扩到十二条明确测试记录后，记录实际名次：该问题仍排第二；“这个程序是从哪里跑起来的”“以前那份过期材料去哪里翻”的目标各排第一，词法均无命中。保留此局限，没有把它改写成普遍召回率收益。重复查询复用缓存；单元验证与本机真实推理分开报告，详见 VER-llm-retrieval。
