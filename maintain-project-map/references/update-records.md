# 开发者选择留存的更新记录

只有用户明确要求“把这次迭代加入更新记录”等情形才读本文并追加。建立更新记录功能、更新项目地图、完成任务或提交 Git，不等于要求记录这次迭代；没有请求时可以保持空列表。

先从本次迭代的已完成改动和用户语境提取：新增或改变了什么能力、为什么值得保留、怎样使用及必要限制。内容面向开发者回忆功能变化；实现规格和验证证据继续在各自记录中维护，通过链接引用，避免复制长文档或执行日志。不要从 Git 提交或旧会话批量补造更新历史。

一轮迭代通常保存为 `records/updates/YYYY-MM-DD-short-name.md`；仅在实际写入时建立文件和文件夹。保留唯一记录 ID，文件名不承担身份；同一天可有多次更新。最小格式：

```yaml
---
id: UPD-reference-integration
kind: update
title: 引用可以接入新的来源
date: 2026-09-16
summary: 新来源复用既有引用能力，开发者可以在接入说明中查到配置方法。
sources:
  - provider: 当前会话来源
    note: 用户明确要求留存本次迭代的位置或必要摘录
---
```

日期使用 `YYYY-MM-DD`。示例中的功能和来源是格式演示；写真实更新时只使用已核对的事实。条目按日期倒序显示在侧栏“更新记录”，不会混入普通模块目录或被当成新的当前需求。

## 链接图中变化

只有涉及架构或流程的变化且有帮助时添加图位置链接。先检查 `project.yaml` 所声明的原生图源，以图中已有的稳定节点 ID 定位；不要把记录 ID 当图节点 ID，也不为每条更新强制改图。

```markdown
新增能力说明见 [[IF-reference|引用接口]]。
图中位置：[来源交接](map-node:workflow/source-handoff)
架构位置：[引用模块](map-node:architecture/reference-core)
```

`map-node:architecture/节点ID` 或 `map-node:workflow/节点ID` 在本张地图里跳到对应图，并把卡片移到画布中央；含特殊字符时按 URL 编码节点 ID。删除或替换节点后，保留历史描述和旧 ID，并在需要时补充后继链接；当前图中不存在的节点会提示失效，不猜一个相近目标。

保存后检查本条更新正文、引用记录和实际图目标，按需刷新 HTML。更新记录无需新增数据库、后台服务或单独的自动维护流程。
