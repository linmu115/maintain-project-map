# 开发者阅读页面

用于生成或解释项目地图的人读视图。普通编码和记录维护无需加载本文或渲染页面。

## 生成

scripts/render_map.py 从当前 project.yaml 与原记录生成阅读入口，默认启动或复用本机 HTTP 服务，并返回阅读 `url`；对用户优先提供这个地址。纯 HTML 导出使用 `--export-only`，具体参数和停止方式见[本地操作](operations.md)。页面携带本次读取的内容指纹与版本，是该次导出的快照；原记录有变化时重新生成并刷新。HTTP 服务不自动更新记录，打开旧页面不能据此认定内容仍是当前状态。

A/B 使用同一份记录与身份：

- A 分面板：项目说明与规格、整体组织、功能路径分别展开；说明下区分做到哪和缺什么。
- B 围绕一项：在当前地图中选择能力、对象、模块或决定，结合相关说明、关系与现状。

## 在线静态发布

用户要从公开仓库直接打开交互地图时，可以用 GitHub Pages 或其他静态托管；仓库的 HTML 文件查看链接本身不是运行页面。使用 `render_map.py <project.yaml> --public-root <允许公开的资料根目录> --output <空目录>/index.html` 生成静态产物，不启动本机服务。根目录必须包含地图及其声明的资料；超出范围的来源会被拒绝，不能通过扩大范围顺带公开个人资料。

公共模式保留文档、图、记录跳转、独立归档页和开发历程叙述。原始会话证据不读取、不打包，页面解释仅本机可用；生成元数据中的本机路径改为相对定位。它不检查正文是否含秘密，发布前核对准备公开的文档。只上传这次新生成的目录，不能混用本机预览产物。系统地图的“进入项目”依赖本机服务，应分别发布需要公开的项目地图。普通本机阅读继续使用原命令。

## 阅读入口

`kind: system` 使用系统概览、接口与关联、收录项目、更新记录入口，图形只展示整体组织。项目卡片先显示语义护照，再从“进入项目”新开目标地图完整阅读页；原系统标签页保持阅读状态。完整说明见[系统地图](system-maps.md)。普通项目的功能路径入口继续保留。

选择默认模式是阅读偏好，不改变地图身份。地图缺少某类材料时显示实际缺口，不生成假的实现进度或猜测流程。

侧栏在两种阅读入口之后显示“更新记录”，按日期浏览 `kind: update` 条目；没有条目时显示空状态。仅由用户明确要求留存某次迭代时追加，见 [写入规则](update-records.md)。记录、导出与阅读不会自动生成更新历史。

## 模块目录与文档链接

B 使用从 records/ 生成的可展开目录，支持更深子目录。模块的 overview.md / index.md / README.md 记录提供目录标题；展开后可读概览与子项。搜索保留匹配记录的祖先目录并展开它们，切换条目保留其他目录的展开状态。绑定的既有资料有独立入口，无需为了页面再写一份目录配置。普通文件夹分组不自动证明模块或接口之间的架构关系。

绑定工作区的静态发现放在“源码入口与依赖”小栏目，不增加独立图谱或聊天流程。关联来源变化的记录在正文前显示待复核提示及路径。已归档说明默认不参与当前目录和搜索；“包含历史”或旧 ID 链接可以打开短定位，再选择当前说明或独立的“查看归档原文”页面。主 HTML 与 docs.json 不内嵌旧正文，功能和需求状态不随说明归档改变。

Markdown 由 [Mistune](https://mistune.lepture.com/en/latest/guide.html) 解析；项目只适配记录身份、来源与页面位置。两种链接可共存：

- 标准 Markdown：`[接口](../core/interfaces/reference.md#错误处理)`。目标已登记为记录时跳到记录与章节；原始文档的精确绑定章节也可匹配。
- Wiki：`[[IF-reference#错误处理|引用接口]]`。优先匹配稳定记录 ID，也支持唯一标题、别名或文件名。标题/文件名重复时不猜目标，改用 ID 或明确相对路径；不要求迁移已有 Markdown 写法。

本地图记录 ID 随文件移动保留；标准相对路径仍应在移动时更新。Wiki 标题可定位，不等于稳定身份；同名消歧由作者完成。浏览器地址保留记录、原资料与章节，支持返回和直接打开。

未作为独立记录的合同或源码，可以在记录的 `sources` 中声明原文件（path 相对 project.yaml），正文用相对当前文档的 Markdown 链接引用。导出器只打包被正文直接链接的已声明文本资料，在页面打开阅读快照，保留原位置和各自指纹，不复制成另一份权威记录。原资料页不会递归导出所有相邻文档。未声明、过大、不支持或失效的目标保留定位信息；不能把未知链接当成已经可用的跳转。普通 LLM 查询不会加载这些人读快照。

正文互链和“提供/消费”关系分开解释：前者让人查阅，后者说明实际协作。关系视图自动生成反向入口，同义反向声明合并后显示，保留不同机制、角色和版本。

## 原生 Archify 嵌入

架构和工作流读取 project.yaml 中明确登记的 Archify JSON，直接使用上游校验、交付和阅读逻辑。图源保留原节点与关系 ID、布局、分组、边界和流程语义；页面不再根据项目记录列表重建图。节点通过独立映射关联项目记录，一项可以对应多个节点，一个节点也可以对应多项说明。

A 的主图和 B 的相关图保留原生图内工具；外层负责项目文档导航与记录搜索。B 有多个关联节点时允许逐个选择，没有关联时给出说明和整体图入口，不虚构聚焦。顶栏固定，侧栏与正文各自滚动。默认图页采用黑白与中性灰，图源详情另提供未改样式的 Archify 原版页面。

点击图卡片后，语义护照直接展示该节点对应的项目条目，保持节点名称与条目按钮的样式，一对多映射完整保留；图下不再重复提供映射抽屉。正文中的 `map-node:workflow/节点ID` 或 `map-node:architecture/节点ID` 链接在当前窗口打开相应图并把卡片放在画布中央；再次点击卡片可查看护照。节点失效时明确提示。

顶栏“返回”恢复上一地图阅读状态，包括页面、条目、页签、搜索、目录展开、正文滚动及图中所选卡片和相机位置。浏览器前进/后退使用同一份页面历史；初次打开没有可回退的地图状态时禁用返回按钮。

图形保持嵌在文档中，默认滚轮滚动正文；点击图形窗口才选中并启用滚轮缩放、空白处左键拖动。点击外部或“返回文档”取消选中，多图至多选中一张。选中状态切换不重载图，不重排正文。图内按窗口宽高适配全图，允许缩到适配比例的 5%；“适应全图”或图内的 0 恢复。

未登记某种图不代表项目失败或功能缺失；有明确需求时再编写图源。已登记图源失效时显示诊断，其他记录继续可读，旧图不能作为本次成功结果。views 中的 JSON 和 HTML 是导出快照，不能据其存在自动认定它们是当前权威资料。

只有新增、修改或比较图源时才查看[Archify 图源维护](archify-authoring.md)。需要解释某项原生图内能力时，按需查阅[上游阅读器说明](../assets/vendor/archify/references/viewer-runtime.md)，无需复制实现图内搜索和拓扑查询。

## 阅读职责

人读页面参考 Linear 的紧凑工作区：白色为主、黑色文字，中性灰分隔，不使用杂色。左侧固定阅读方式、搜索和可滚动目录；正文使用紧凑页签与列表。项目身份和快照信息收进顶栏详情，地址记录模式、条目、面板与页签。小屏用目录开关访问导航。图内原生阅读引导以可展开区域呈现，内部按实际内容高度排布，超出时滚动整个引导内容区；不要用小比例高度压缩网格行再隐藏溢出。样式属于按需生成的人读资产，不放进 Skill 入口。

页面服务开发者理解、浏览和查找。提问继续使用现有会话 harness，不增设聊天框、发送桥接或专用提问入口。LLM 根据用户提供的名称、位置或引用查询原记录，不假定知道用户正在看哪页。

先解释项目能做什么、对象是什么、为什么这样协作，再给具体字段和代码入口。人读说明来自有来源的记录，不能只展示机器字段。不同阅读方式不各自维护一份需求。

实现记录优先解释当前行为、用法与已知限制。验证记录独立访问；已知失败或未验证状态会影响使用时，应在实现说明中简短提示。不能把提议写成已确定缺口，或把文档已经写好称为功能已经实现。

外部地图只显示项目 ID、必要记录 ID 与简短关系，通过已登记位置按需打开。目标不存在时保留引用；不自动加载相邻项目全图。

页面切换、搜索、展开和已生成图的浏览由本地代码完成，不调用模型。图源明确使用远程品牌素材时，原生 Archify 的素材获取可能联网。原生交付回执与浅色适配副本分别记录文件指纹；图通过校验不等于项目功能已经实现或验证，也不代替实际视觉检查。

画布层级：外部选中边框、工具栏和 SVG 视窗固定；仅内部图形分组应用缩放和平移。完整图边界应包含外绕连线、标签及留白，不能只按节点外框裁切。完整图导出要清除交互相机变换。
