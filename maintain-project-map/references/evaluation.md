# 评估这个 Skill

仅在开发、评估或诊断本 Skill 时读取；不作为被维护项目每次开发的固定步骤。

## 主对照

相同任务、原始材料、模型、工具与预算，比较无本 Skill 与可自然选用本 Skill。隔离工作目录、Skill 可见性及各组轨迹；无 Skill 组允许正常记笔记。初次建图、后续维护、返工和失败尝试均计入。

用逐步提出需求、改口、一次小修改、跨项目接口与换会话接续的场景观察长期行为。模拟用户按冻结的意图与披露规则分别回应两组，不透露另一组结果；未告知的要求不记成遗忘。

## 判断

- 实现是否满足已告知且当前有效的要求，是否出现缺陷。
- 来源、旧称、退役后继是否可准确查回；未知与未覆盖是否如实说明。
- 提议、有效需求、实际实现、验证与探索状态是否区分。
- 是否减少用户纠正、重复解释、无关扫描和额外停顿。
- 小任务是否误触发，是否发生无关资产修改。
- 开发者能否理解接口、设计理由和当前情况。模型扮演读者不替代真人反馈。

同时比较相同预算下的质量，以及达到相同验收要求的总成本。按宿主运行记录统计输入、输出、缓存、耗时；核对明细是否包含于总量、数据是累计还是单次，避免重复计算。不可用的计数保持不可用。模拟与评判模型费用另列。

## 收窄与改进

评估组合项目能力时，可选三类有明确来源的小场景：插件组合中提供方一份合同、消费者各自接入并双向定位；同一系统有 Harness 与业务插件两类 Adapter，要求正确拆分且共享定义不复制；只有一个简单职责的小项目，检查是否无端生成多层空目录。检查实际产物能否查回职责和接口、图中是否可定位负责组件，不以出现“模块”“接口”等关键词计为通过。此类行为验证与完整多轮对照仍需分别报告。

先验证单个小场景的运行、隔离与计数，再增加重复与任务类型。没有改善结果却增加开销时，删减规则或读取范围；不能仅增加文档来修复误触发。

机械脚本的单元/集成检查、一次独立前向任务和完整多轮基线实验分别报告。前两者不能证明普遍正向提升，不报告未实测的 token 节省百分比。

普通工作中不要求模型填写成本报告或重复评估；从既有运行记录汇总。模型或宿主变化、实际回归时再复查有关场景。
