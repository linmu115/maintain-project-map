# 检索与来源

已有精确位置时直接读取原文。这里用于模糊查回、来源核对、长会话和跨项目定位，不要求普通修改逐条执行。

## 从当前问题缩小范围

- 已知记录 ID：读取该记录，区分当前状态与历史去向。
- 当前规格：先查有关要求、接口和实现；需要理由时再追来源。
- 当时的选择：读对应决定和原消息，核对后来是否被替代。
- 只记得叫法：搜索中文词、别名和关键行为；没有命中时按证据扩大范围。内置搜索是词面匹配，不宣称语义召回。
- 旧名或退役功能：包含历史项，先解释退役/合并原因与后继。
- 外部引用：用项目 ID 和可选记录 ID 解析目标，只打开必要内容。找不到目标保留原引用；多个工作树不猜一个位置。

地图脚本的 search/read/related/resolve 返回候选或正文与精确位置，命令见[本地操作](operations.md)。命中不等于核实；读取被截断时使用返回的后续位置继续。关系只描述已登记范围，不能证明没有其他消费者。

## 长会话

优先使用宿主现成的任务读取工具及分页。需要补查且原记录可读时，只定位用户指定任务对应的文件，不扫描所有会话。

本 Skill 提供 scripts/search_session.py，读取明确指定的 Codex JSONL 文件中的可见消息，默认只查用户消息。它不读取模型内部推理、工具输出或未知类型作为消息，也不自动复制会话进入地图。

搜索回执包含消息 ID、任务 ID（源文件提供时）、文件位置、文本摘要校验值和覆盖范围。没有原生 ID 时使用文件位置与摘要，并明确身份较弱。特别长的消息按 Unicode 码点分段；不同工具不能假设偏移单位相同。

这只是一个 Codex 原记录适配器；其他宿主继续使用各自接口。格式未覆盖、正文不可访问、搜索无命中分别说明，不能都当作历史中不存在。

## 引用与有效性

来源可保存 provider/thread_id/message_id，或文件/章节/版本，加少量必要摘录；代码可以保存路径、符号与 Git 提交。历史命令是证据，不获得当前执行权限。

发生冲突时回看后续修订与当前用户要求。实现观察不能反向改写需求。源文件移动或变化后核对位置；不能把相似的新对象冒充原条目。

复用仍适用的已读内容。索引和页面可重建，原始文件与宿主消息仍是来源；不要用全量历史注入代替检索。Skill 不控制宿主压缩或承诺模型永久记住全部上下文。
